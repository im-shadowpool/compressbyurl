# 07 — SEO Master Strategy

SEO is a dedicated product workstream for CompressByURL.

## Strategic layers

### Layer 1 — established image-tool searches

- image compressor
- compress image
- compress JPG
- compress PNG
- compress WebP
- resize image
- image converter
- JPG to WebP
- PNG to WebP
- compress image to 100KB / 200KB / 500KB

### Layer 2 — differentiation searches

- compress image from URL
- compress by URL
- image URL compressor
- optimize image from URL
- website image optimizer
- website image scanner
- find large images on website
- optimize images from webpage
- download images from webpage
- compress all images from website

Layer 2 should become the brand moat.

## Important principle

The brand name can reinforce relevance, but rankings come from useful working tools, strong intent match, page quality, speed, crawlability, authority, internal linking, and real user value. Do not rely on the exact-match name alone.

## Every tool page needs

1. unique title/meta/H1
2. real functional preset
3. server-rendered explanatory copy
4. supported inputs/outputs
5. privacy statement
6. concise how-it-works
7. examples/use cases
8. useful FAQ
9. related tools
10. internal links
11. structured data where valid

## Programmatic SEO

Allowed:
- shared route registry
- shared tool engine
- shared layout components

Not allowed:
- hundreds of near-identical pages
- swapping only a number/keyword
- fake FAQs
- doorway pages
- pages with no unique behavior/value

## Internal linking

Build topical clusters. Example:

`/compress-png → /png-to-webp → /compress-image-to-100kb → /compress-image-from-url → /website-image-optimizer`

Use contextual links, not keyword footer spam.

## Technical SEO

Required:
- server-rendered important content
- unique metadata
- canonical
- sitemap
- robots
- OG/Twitter
- semantic headings
- breadcrumbs where useful
- WebSite schema
- SoftwareApplication schema where valid
- Article schema for editorial content
- fast LCP/INP/CLS
- stable routes
- noindex temporary scan/result URLs
- correct redirects after route changes

## Search Console iteration

Use real query/page data to decide:
- which target-size thresholds deserve pages
- which URL phrases users actually use
- where CTR is weak
- where pages cannibalize
- where internal linking is weak
- which competitor queries appear

# 19 — Competitor Targeting

## Initial competitor set

- TinyPNG
- Squoosh
- CompressImage.io
- iLoveIMG

## Non-negotiable rule

Never publish a competitor comparison from model memory alone. Re-verify the live product before publication and periodically after launch.

Before publishing, verify:
1. current feature set
2. supported formats
3. privacy/local-processing behavior
4. batch behavior/limits
5. target-size capabilities
6. URL/page scanning behavior
7. pricing/limits if mentioned
8. review date

## Good positioning

“CompressByURL is designed for users who want browser compression plus direct image-URL and webpage-image workflows.”

## Avoid

- “10x better”
- “always smaller”
- “competitor never/always uploads files”
- inaccurate price/limit claims
- insulting competitor copy

## Comparison dimensions

- local processing
- direct image URL
- webpage scan
- target-size mode
- batch handling
- ZIP
- static format support
- resize
- naming rules
- offline/PWA
- pricing/usage limits if verified

## Content quality

A competitor page should be useful even if the comparison table were removed. Include real guidance about workflow differences, privacy, target-size compression, and URL-based optimization.
